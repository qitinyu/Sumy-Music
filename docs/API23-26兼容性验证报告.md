# 低版本（API 23 / 24）兼容性验证报告

> **结论先行**：已定位「低版本设备无法打开应用」的根因并修复。
> 修复经静态验证（真机崩溃日志 + SDK 类型定义双向确认）与 **API 26 真机复测**（2026-09-24，
> 详见第六节）：冷启动无闪退、回归项全部通过、无 `Cannot read property` 异常、
> 高版本沉浸光感材质未被误降级。
>
> **兼容范围**：因 DevEco Studio 本地未安装 API 24 SDK，最低版本已由 `6.1.1(24)` 下调为
> **`6.1.0(23)`**（`build-profile.json5`）。因此本报告同时覆盖 API 23 与 API 24。

## 一、问题现象

更新日志中长期未勾选的条目：

```
- [] 修复应用在API24设备无法打开的问题 #2076
```

表现为应用在低版本设备上**启动即闪退**（并非功能异常，而是完全打不开）。

## 二、根因（已确认）

### 2.1 崩溃日志（项目自带，实证）

文件：`ziyuan/log/1.txt`（崩溃版本 `2.0.7.7`）

```
Device info:emulator
Build info:emulator 6.1.0.126(SP1DEVC00E120R4P11)
Version:2.0.7.7
Reason:TypeError
Error message:Cannot read property THICK of undefined
Stacktrace:
    at immersiveMaterial shym1032 (entry/src/main/ets/utils/MaterialCompat.ets:101:52)
    at anonymous shym1032 (entry/src/main/ets/pages/XuanchuangTab.ets:1985:42)
    at initialRender shym1032 (entry/src/main/ets/pages/XuanchuangTab.ets:1960:13)
    at initialRenderView (.../stateMgmt.js:9004:1)
E C03947/AceStateMgmt: FIX THIS APPLICATION ERROR:
    @Component 'XuanchuangTab'[69] has error in update func: Cannot read property THICK of undefined
```

两个关键点：

1. 崩溃发生在 **`initialRender` 阶段**（首帧渲染前）→ 表现为「应用打不开 / 闪退」，而非运行中偶发。
2. 崩溃点是 `uiMaterial.ImmersiveStyle.THICK`，说明 **`uiMaterial.ImmersiveStyle` 为 `undefined`**。

### 2.2 SDK 类型定义证据

对本地 SDK 做交叉比对（`D:\HM\Harmory-sdk\23`、`D:\HM\Harmory-sdk\26.0.0`、
`D:\DevEco Studio\sdk\default`）：

| API | 项目 | API 23 SDK | API 26 SDK |
| --- | --- | --- | --- |
| `uiMaterial` | `@kit.ArkUI` 导出 | **不存在** | 存在 |
| `systemMaterial(...)` | `CommonMethod` | **不存在** | `@since 26.0.0` |
| `SystemUiMaterial` | 类型 | **不存在** | `@since 26.0.0` |
| `backgroundEffect(...)` | `CommonMethod` | `@since 12` ✅ | ✅ |
| `SystemMaterialParams.systemMaterialEffect` | HDS | — | `@since 6.1.0(23)` |
| `hdsMaterial.MaterialType.IMMERSIVE` | HDS | — | `@since 6.1.0(23)` |

即：**`uiMaterial` / `systemMaterial` 是 API 26 才引入的能力**，低于 26 的设备上运行时确实不存在。

### 2.3 触发链路

`V2.0.7.7` 的 `MaterialCompat.immersiveMaterial()` **既无版本守卫、也无 try/catch**：

```ts
static immersiveMaterial(style?, options?): uiMaterial.Material {
  const s = style !== undefined ? style : MaterialCompatStyle.REGULAR
  let immersiveStyle: uiMaterial.ImmersiveStyle
  switch (s) {
    case MaterialCompatStyle.THICK:
      immersiveStyle = uiMaterial.ImmersiveStyle.THICK   // ← 低于 API 26 此处抛 TypeError
```

而 `XuanchuangTab` 在 `bindSheet` 的 `systemMaterial:` 参数中**无条件**调用它；
该参数在构建组件树时即求值，于是异常在首帧渲染前抛出，应用直接打不开。

## 三、修复内容

### 3.1 版本守卫

`CompatUtils.isImmersiveSupported()` 以 `deviceInfo.sdkApiVersion >= 26` 判定，低版本直接降级。

### 3.2 运行时能力探测（本次新增，纵深防御）

仅靠版本号判定不够——**崩溃日志中的模拟器 `Build info: 6.1.0.126`，
其 SDK 版本上报与能力注入可能不一致**（设备上报 api 26，但 `ImmersiveStyle` 仍为 `undefined`）。
故在 `MaterialCompat.immersiveMaterial()` 内增加 `typeof` 能力探测：

```ts
try {
  if (typeof uiMaterial.ImmersiveStyle === 'undefined') {
    return undefined
  }
  ...
} catch (_e) {
  return undefined
}
```

形成「**版本判定 → 能力探测 → 异常兜底**」三层防护。
返回 `undefined` 时，调用方 `.systemMaterial(undefined)` 与 `systemMaterial: undefined`
均表示「无材质效果」，自动回退到 `backgroundEffect` 模拟路径（**API 12+ 可用**，
故 API 23 亦安全）。

### 3.3 调用点守卫盘点

| 位置 | 形式 | 状态 |
| --- | --- | --- |
| `BottomPlayer.ets:185` | `if (supportImmersive)` 分支 | ✅ 已守卫 |
| `FloatingTabBar.ets:236` | `if (supportImmersive)` 分支 | ✅ 已守卫 |
| `FloatingActionPopup.ets:53,145` | `if (supportImmersive)` 分支 | ✅ 已守卫 |
| `FullPlayerPage.ets` ×5 | `this.supportImmersive ? … : undefined` | ✅ 已守卫 |
| `QinseTab.ets:371` | 三元守卫 | ✅ 已守卫 |
| `XuanchuangTab.ets` ×10 | `systemMaterial:` 直接调用 | ✅ 由 `immersiveMaterial()` 内部三层防护保证 |

> `XuanchuangTab` 的 10 处未在调用点做三元守卫，安全性由函数内部防护保证。
> 若后续要统一风格，可参照 `FullPlayerPage` 改为三元写法。

## 四、降到 API 23 的可行性核查

已确认项目用到的能力在 API 23 均有定义：

| 依赖 | `@since` | API 23 可用 |
| --- | --- | --- |
| `backgroundEffect`（材质降级路径） | 12 | ✅ |
| `HdsTabs` / `HdsNavDestination` / `hdsEffect` | 5.0.0(12) | ✅ |
| `systemShare`（ShareKit） | 4.1.0(11) | ✅ |
| `authentication`（AccountKit） | 4.1.0(11) | ✅ |

并在编译用 SDK 中检索 `@since 24.` / `@since 25.` 声明：**0 处**。
即降低兼容下限至 API 23 无需额外代码改动。
